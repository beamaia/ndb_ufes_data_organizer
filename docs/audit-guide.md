# Manual Audit Guide

Use this guide to manually verify generated code and artifacts before cleanup, publication, or commit.

## Audit Principle

Trust artifacts only after checking data lineage and invariants. Generated prose, script comments, and filenames are not evidence by themselves.

## 1. Repo State and Ignored Files

Run:

```bash
git status --short
git status --ignored --short
git ls-files
```

Check:

- Which files are tracked, modified, deleted, or untracked.
- Whether `data/` is intentionally DVC-managed and Git-ignored.
- Whether `results/` contains generated artifacts that should remain untracked.
- Whether root Markdown files are temporary notes or canonical docs.
- Whether accidental files exist, such as the empty file named `2`.

Current known state:

- many root Markdown files are untracked;
- `mkdocs.yml` and `docs/` are untracked;
- `scripts/phase3.py` and `scripts/phase4.py` are empty;
- `main.py` contains an obvious typo: `neimport os`.

## 3. Phase 1: Feature Extraction

Open in this order:

1. `scripts/phase1.py`
2. `scripts/src/phase1/extraction_func.py`
3. `scripts/src/phase1/feature_extractor.py`
4. `scripts/src/models/model_loader.py`
5. `scripts/src/models/model_wrappers.py`
6. `scripts/src/phase1/config.yaml`

What it should do:

- create origin-patch mapping;
- load frozen pretrained models;
- extract patch embeddings;
- save embeddings grouped by origin;
- save run metadata.

Focal points:

- path drift: `patch/` versus `patch_level/`;
- cache behavior: cached embeddings can hide changes;
- preprocessing: ImageNet normalization is applied broadly, even for pathology foundation models;
- wrapper behavior: models with different output shapes are forced through a common interface;
- metadata wording: counts may refer to origins even when labeled as patches.

Evidence to collect:

- number of origins in mapping;
- total patch count across mapping;
- one embedding file shape per model;
- failed model list and failure reason.

## 4. Phase 2: Morphology Tuning

Open:

- `scripts/phase2.py`
- `scripts/src/phase2/config.yaml`
- Phase 2 tuning outputs generated by the current rerun

What it should do:

- discover Phase 1 embedding files;
- mean-pool patch embeddings to one vector per origin;
- run PCA and K-Means over a grid;
- repeat K-Means runs;
- save per-run, averaged, and selected-parameter outputs.

Focal points:

- model-name parsing may collapse files such as `efficientnet_b0` and `efficientnet_b1` into one `efficientnet` key;
- highest silhouette may prefer too few clusters for useful fold stratification;
- existing folds may reflect an older morphology-clustering configuration;
- selection must not depend on downstream model performance.

Audit questions:

- Are all intended embedding files discovered?
- Are any discovered models overwritten by filename parsing?
- Are cluster sizes reasonable?
- Is the chosen model/config justified for fold stratification, not just mathematical cluster separation?
- Are repeated runs summarized with mean and standard deviation?

## 5. Leakage Review

Acceptable:

- frozen external pretrained embeddings used for unsupervised fold stratification;
- choosing folds before downstream model training.

Leakage or selection-bias risks:

- patch-level random splitting;
- selecting folds after downstream test results;
- fine-tuning embeddings on all labels before fold creation;
- using the same origin in train and test through different patches.

Required invariant:

```text
one origin_id -> one fold
```

## 6. Phase 3: Fold Creation

Open:

- `scripts/phase3.py`
- `scripts/src/phase3/phase3_fold_creation.py`
- `scripts/src/phase3/phase3_fold_visualization.py`
- existing fold CSVs under `data/ndb_ufes/*/csvs/`

What it should do:

- load origin/patch metadata;
- apply chosen PCA/K-Means clustering;
- assign morphology clusters;
- create stratification variables;
- assign origins to folds;
- broadcast fold assignments to patch rows.

Focal points:

- top-level `scripts/phase3.py` is empty;
- implementation file may write to `results/phase3_fold_creation/`, while current artifacts are under `data/ndb_ufes/`;
- existing folds may rely on an older morphology-clustering configuration;
- default fold-construction variables should be origin diagnosis, morphology cluster, gender, and age group;
- inspect `stratification_variables_audit.csv` before accepting any rerun;
- high-missingness fields such as `Not informed`-heavy clinical variables must not silently enter `stratification_key`;
- some docs describe old fold-column formats that no longer match current CSVs.

## 9. Documentation Cleanup

After audit, decide for each root Markdown file:

- promote content into `docs/`;
- archive as historical notes;
- delete if superseded.

Do not commit both root duplicates and docs pages unless each has a distinct purpose.

## Final Acceptance Checklist
